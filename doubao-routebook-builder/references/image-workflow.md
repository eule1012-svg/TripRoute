# 图片获取与验证流程（image-workflow）

行程中**每一个**景点、酒店（外观+房间）、交通方式、体验活动都必须配真实图片，且用户端必须能显示。

## 一、图片来源（按优先级）

1. 用户提供的图片（第一优先，不擅自替换）
2. 图片生成（无可用素材时；prompt 写明风格/构图/配色，与视觉方向一致）
3. 外部检索：image_search 等工具找真实实体图（景点、酒店、交通工具、演出等具象内容）

## 二、禁止事项（多次踩坑）

- **禁止直接引用 Booking/Agoda/携程等 CDN 直链**（防盗链，用户端裂图/空白）——必须下载后重新上传/本地化
- 禁止引用图片搜索返回的临时 URL 直接写进 HTML（会过期）
- 禁止 JS 数组拼图片路径、data-src、srcset、poster 等非 src/CSS url() 引用（发布后裂图）
- 禁止用 SVG/CSS 几何图冒充景点、酒店、人物等具象画面

## 三、获取流程

1. 对每个目标（景点/酒店/交通/体验）发起真实图片搜索（拆分关键词，如"岘港 美溪海滩"、"Furama Resort 房间"）
2. 下载候选图到工作目录 `assets/`（`curl -L -o`），**用读图能力实际看过**：内容对得上、清晰完整、无水印、非防盗链占位图
3. 不合格的换图或改搜；酒店至少外观 1 张 + 房间 1 张
4. 图片路径写 `<img src="assets/imgNN.jpg">`（本地电脑相对路径）或内嵌（云电脑，见验证规范）

## 四、压缩与体积（云电脑交付红线）

交付内嵌 HTML 总大小必须 <5MB（超过会有交付警告/失败）。压缩脚本：`scripts/compress_images.py`。

- 目标：单图长边 680–820px，JPEG quality 48–60
- 45 张图规模下，压缩后总量约 2.6MB，内嵌版约 4.9MB——照此比例控制图片数量与体积
- 主图（hero）可 16:9 大图，其余按用途定比例（见 visual-design）

## 五、验证

- 所有图片下载后 `curl -sL -o /dev/null -w "%{http_code}"` 确认 200（注意：HEAD 请求会被部分 CDN 拦截返回 404，必须用 GET）
- 交付前截图逐张核对图片显示正常、比例正确、无裂图
- 如有图片无法获得可访问版本：该条目保留文字说明并标注"图缺失"，不得用占位图充数
