# 跨国商务考察+旅游路书生成器

把"目的地 + 诉求 + 预算"转化为一份可执行、可验证、图文并茂的 HTML 路书。本 Skill 源自越南+老挝 15 天商务考察路书的完整实践，沉淀其验证方式、排版布局与板块内容；后续任何国家/地区方案都按同一套规范生成，但需求采集、天数、板块取舍按实际诉求调整。

## 总流程

1. **需求采集**（必须先完成，不可跳过）→ 读 `references/intake-questions.md`，按清单向用户提问，补齐所有关键因素后生成任务画像表
2. **调研与素材**（按画像路由）→ 目的地基础、交通、住宿、体验、价格核实、图片获取
3. **生成 HTML** → 拷贝 `assets/routebook-template.html` 为工作文件，按各 reference 填充
4. **验证** → 按 `references/verification.md` 自检（桌面+移动）、内嵌、交付

## 一、需求采集（第一步，强制）

生成任何方案前，必须基于 `references/intake-questions.md` 的问询清单与用户确认以下核心维度，**不可凭默认值猜**：

- 出行国家/地区（可多国，注意入境顺序与跨境交通）
- 出行月份/具体出发日期（决定天气、旺季、节日）
- 出行人数与构成（单人/双人/家庭/团队，是否含老人儿童）
- 行程天数
- 预算：人均红线与总预算（明确货币；决定住宿档次与航班选择）
- 住宿条件：档次、位置偏好、是否接受青年旅舍/混合住宿及比例
- 交通偏好：飞机/大巴/火车/自驾，是否要特色交通（跨境大巴、景观铁路、卧铺等）
- 是否需要导游/讲解
- 是否需要当地特色活动/体验（烹饪课、一日游、节庆等）
- 饮食需求（特色美食、忌口、素食等）
- 文化需求（古城、寺庙、博物馆、非遗等）
- 商务考察需求（考察行业、目的：如电子支付、电商、供应链、投资开户等）
- 其他重要因素（见清单：签证、设备携带、宗教禁忌、节奏强度、是否要报价单等）

将确认结果整理为任务画像表（国家/日期/天数/人数/预算/住宿/交通/活动/饮食/文化/商务/备注），作为后续所有决策依据。**用户诉求不同（如无考察内容、天数不同、考察别的行业）时，按画像裁剪板块**（见"板块路由"）。

## 二、调研与素材

按画像展开调研，全部事实必须可追溯（来源 URL），价格必须核实（见 `references/price-verification.md`）：

- **目的地**：签证政策、天气与穿衣、货币与汇率（当地货币+人民币换算）、电源插头、无人机等设备规定、节日与活动日历、宗教与文化禁忌
- **交通**：航班（含直飞）、跨境铁路/大巴、当地打车/包车，票价、时刻、预订入口
- **住宿**：按住宿策略筛选（默认 70% 高性价比青旅 + 30% 特色酒店，可按预算与画像调整），真实评分、真实价格、位置
- **体验活动**：当地评分高、评论多的特色体验（Klook/KKday/官网），含价格与预订链接
- **商务考察**（如有）：考察行业生态、支付/平台/渠道格局、落地路径（公司注册/开户/支付接入/费用），逐项标注核实状态（已核实/待现场确认/未核实）与来源
- **图片**：所有行程涉及的景点、酒店（外观+房间）、交通方式、体验活动，必须找真实图片并按 `references/image-workflow.md` 下载、验证、本地化

## 三、板块路由（按画像裁剪）

默认 8 大板块（见 `references/layout-spec.md`），按画像调整：

| 板块 | 条件 |
|---|---|
| 01 路线总览 | 恒有（真实地图 + 城市节点 + 总览表） |
| 02 每日行程 | 恒有（展开卡片 + 时间线 + 图片 + 筛选标签） |
| 03 必体验 | 恒有（TOP N 卡片，N 按天数 4–8） |
| 04 商务考察专题 | 仅当画像有考察需求（按考察行业定制内容；无考察则删除该板块） |
| 05 住宿 | 恒有（住宿策略说明 + 精选酒店/青旅卡片） |
| 06 预算 | 恒有（当地货币+人民币，人均红线仪表） |
| 07 行前信息包 | 恒有（签证/天气/货币/电源/穿搭/设备规定） |
| 08 预订入口汇总 | 恒有（票务/住宿/体验的官方入口） |

## 四、生成 HTML

1. 拷贝 `assets/routebook-template.html` 到工作目录（建语义化目录，如 `<destination>-routebook/`）
2. 按 `references/visual-design.md` 确认配色（默认浅色系；用户点名深色/其他色系才改）
3. 按 `references/layout-spec.md` 填充 8 板块
4. 按 `references/map-spec.md` 制作真实地图（SVG 经纬度投影）
5. 图片路径必须写在 `<img src>` 属性或 CSS `url()` 中（禁 JS 拼图路径、禁 data-src）
6. 禁 emoji（用内联 SVG 图标）；表格显式列宽（table-layout:fixed + colgroup）

## 五、验证与交付

严格按 `references/verification.md` 执行：shot.py 桌面+移动自检（lint 0）、embed.py 内嵌、present_files 交付。交付说明须写明：核实范围、未核实项、汇率基准日、图片来源处理方式。

## 六、关键红线（多次踩坑沉淀）

- 图片禁止直接引用 Booking/Agoda/携程 CDN 直链（防盗链，用户端无法显示）；必须下载 → 压缩 → 本地化 → 内嵌
- 交付的内嵌 HTML 总大小须 <5MB（压缩图片：长边 680–820px、quality 48–60）
- 所有价格须当地货币+人民币括号换算（标注汇率基准日与来源）；来源须可追溯
- 地图必须按真实经纬度投影，城市相对方位与真实地图一致；图例区分交通方式线型
- 每日卡片布局：行程（时间线）第一行、图片第二行；行前信息包 4 卡 2×2（移动端单列）
- 涉及陪玩/非法服务等诉求：拒绝并引导至合法本地互动体验，不进入方案
- 云电脑交付前必须 embed.py 内嵌（本地电脑用相对路径 + 提醒连目录发送）
